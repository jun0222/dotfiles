# /todo — 雑なメモをTODOリストに整理する

やること・やったこと・気になることを雑に話すと、指定ファイルへ箇条書きで整理して書き込む。

## 使い方

```
/todo [--file <パス>] [初期メモ...]
```

| 引数 | 説明 | デフォルト |
|---|---|---|
| `--file <パス>` | 書き込み先ファイル | `~/Desktop/todo.md` |
| `[初期メモ]` | 最初から渡すメモ（省略可） | — |

## 処理内容

### 1. 引数をパース

- `--file <パス>` → 書き込み先を設定（`~` は展開する）
- 残りのテキスト → 初期メモとして扱う
- `--file` 未指定時は `~/Desktop/todo.md` をデフォルトにする

### 2. 対話フェーズ（ヒアリング）

以下のメッセージでユーザーに入力を促す:

```
📋 TODOを整理します。やること・やったこと・気になることを雑に教えてください。
   複数あれば続けてどうぞ。「整理して」と言ったらまとめます。
   書き込み先: <パス>
```

ユーザーが「整理して」「まとめて」「書いて」「ok」「完了」「done」のいずれかを含むメッセージを送った時点でヒアリングを終了し、次のステップへ進む。

初期メモがあった場合はそれも含めてヒアリングを行う（追加があれば聞く、なければそのまま整理）。

### 3. 内容を分類・整理する

集めたメモを以下のカテゴリに分類する（該当するものだけ出力）:

| カテゴリ | 見出し | 対象 |
|---|---|---|
| やること | `## TODO` | まだ手をつけていないタスク |
| 進行中 | `## DOING` | 今やっている・途中のタスク |
| 完了 | `## DONE` | 終わったこと・やったこと |
| メモ | `## MEMO` | 調べたこと・気づき・ゆるい記録 |

各カテゴリは箇条書き（`- `）で列挙する。細かい粒度に分解できる場合は分解して書く。
曖昧な内容は補足コメントを `<!-- 元メモ: ... -->` として行末に付ける。

整理後のプレビューをターミナルに出力してユーザーに確認を求める:

```
以下の内容で <パス> に書き込みます。よろしいですか？ [y/N/編集]

---
<整理内容のプレビュー>
---
```

- `y` → 書き込みへ
- `N` / 空 → 中断
- `編集` → 特定の項目を修正してから書き込む

### 4. ファイルに書き込む

#### ファイルが存在しない場合

以下のテンプレートで新規作成する:

```markdown
# TODO

最終更新: YYYY-MM-DD HH:MM

## TODO

## DOING

## DONE

## MEMO
```

#### ファイルが存在する場合

既存ファイルを Read して、各セクションの末尾に新しい項目を**追記**する。
既存の項目は変更しない。セクションが存在しない場合はファイル末尾に追加する。

`最終更新:` の日時を現在時刻に更新する。

### 5. 完了メッセージを出力

```
✓ <パス> に書き込みました（TODO: N件 / DOING: N件 / DONE: N件 / MEMO: N件）
```

## ルール

- 既存の項目は**絶対に削除・変更しない**（追記のみ）
- 重複するタスクが既存にある場合はスキップして警告する
- ユーザーの言葉のまま書かず、簡潔な動詞+目的語形式に整える（例: 「○○をやる」→「○○を実装する」）
- 「整理して」と言われるまではヒアリングを続ける

## 実行例

```
/todo
/todo --file ./TODO.md
/todo --file ~/Desktop/work-todo.md APIのエラーハンドリング直す、テスト書いてない
/todo 今日やったこと: デプロイ対応、PR出した。明日やること: レビュー待ち対応、ドキュメント更新
```
